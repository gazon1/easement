# Polyglot architecture enforcement: rule semantics and agent workflows

Checked on 2026-11-04 against first-party documentation and the current local easement README. This is a documentation comparison; no competitor was installed or benchmarked. “Not verified” identifies the limit of this investigation, rather than proving absence. This supplements [the emerging-competitors survey](easement-competitors.md).

## Assessment

Polyglot boundary enforcement, baselines and agent interfaces have direct competitors. Sonargraph is substantially more than architecture scoring: it enforces a declarative architecture DSL; its Zügel companion adds an MCP workflow. Architect Genesis and MKanhan/archlint also enforce explicit boundaries. Easement's useful comparison is therefore its particular CLI workflow and common component policy, including source dependencies, package declarations and Cargo features, with explicit qualifications on incomplete analysis. No equivalent for that complete combination was established here. This is an inference from the evidence below, not a uniqueness claim.

## Easement: the reference behavior

These are current local documented capabilities, not assumptions based on a language count:

- `may_depend_on` permits component edges; `must_not_depend_on` overrides allowances. `allow_importers` restricts the provider's consumers. `public` restricts exported paths; `public_symbols` restricts exported names for the languages supporting symbol-use rules. [Configuration and public API](../configuration.md#easementyml), [importers](../configuration.md#who-may-import-a-component), [symbols](../configuration.md#symbols).
- `layers` permits downward access. A `closed` layer prevents skipping it; explicit `may_depend_on` and `common` can still allow listed edges. Named placeholders constrain equal slice identities; `isolated` forbids dependencies between instances. [Layers](../configuration.md#layers-and-forbidden-dependencies), [slices](../configuration.md#slices).
- `must_not_reach` rejects an indirect chain even when its individual hops are allowed. With `reach: symbols`, references follow method/function definitions where available, conservatively falling back to file dependencies. `why` and `impact` remain file-based. [Reachability](../configuration.md#reaching-through-others).
- A baseline legalizes identified debt and detects stale entries; ordinary regeneration only shrinks it. `--diff` judges changed importing lines against a Git merge-base, so a rule-only change requires a full check. [Baseline](../adoption.md#baseline-adopting-on-an-existing-project), [diff](../adoption.md#diff-mode-judging-a-pull-request).
- `manifests` checks imported packages against declarations; `packages` adds edges from Cargo, npm and Go manifests. A component can own a Cargo `feature/<name>` part and constrain who activates it. This is a declared activation graph, with documented limits such as not modeling `default-features = false`. [Declared dependencies](../configuration.md#declared-dependencies).
- JSON exposes partial-analysis reasons, uncovered files, cache use and unreliable suggestions. Scope-limited success is explicitly partial. Missing/failed indexers are errors, rather than heuristic fallback. SCIP covers eight language groups; Kotlin and Swift use tree-sitter. Symbol-use enforcement is narrower: Go, TS/JS, Python, Rust and Ruby. [Languages](../languages.md#languages), [indexers](../languages.md#indexers), [cache](../languages.md#index-cache).

The README comparison's statement that easement has no naming or call-chain rules is stale relative to its documented `defines` and `reach: symbols` sections. Neither makes it a general semantic architecture-test framework. [Type naming](../configuration.md#names-of-types), [reachability](../configuration.md#reaching-through-others).

## Sonargraph: exact rules, with a richer composition model

The main product advertises Java/Kotlin, C#, Python, Go, TypeScript and C/C++; do not transfer this matrix to Zügel. [Product scope](https://www.hello2morrow.com/products/sonargraph).

| Intent | Sonargraph semantics | Easement comparison |
| --- | --- | --- |
| Select code and permit edges | Artifact `include`/`exclude` selects elements; `connect to B` connects a consumer connector to a provider interface. Default ports contain the artifact's elements. | `in` selects a component; `may_depend_on` grants access. Selection is not itself permission. |
| Narrow visibility | Named interfaces select exposed elements; named connectors select consumers. Hidden nested artifacts are omitted from the parent's default interface; `local` removes them from its default connector. | Public paths/names and `allow_importers` overlap, but do not provide the same nested, named-port model. |
| Strict/relaxed layers | `strict` grants access to the next sibling; `relaxed` to all following siblings, through their default interfaces. | Downward `layers` resembles relaxed layering; closed barriers model mandatory intermediate layers. Neither is a literal keyword translation. |

The semantics and exceptions are documented in [Interfaces and Connectors](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_interface_connectors.html). Sonargraph's `public` artifact is accessible to preceding siblings; it is not easement's public-path filter. The cited [grammar](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_grammar.html) uses `connect`, interface filtering and modifiers, not easement's global deny-overrides-all rule. Do not invent equivalent `allow`/`deny` keywords.

Sonargraph models vertical slices by applying a reusable layering aspect inside each subsystem, exposing selected layers through an interface, then connecting subsystem clients to it. Its example connects `Order` to `Customer.IService` and `Product.IService`, where `IService` exports only Service and Model. Easement's `<feature>` placeholders express repeated slice identity compactly; the Sonargraph example expresses named subsystem interfaces and reusable internal structure. Both address slices, with different abstractions. [Official worked example](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_organizing_code.html).

`connect to Foundation transitively` adds Foundation access to Controller's default interface, so Controller clients may access it too. This is permission re-export, **not** a demonstrated equivalent of easement's `must_not_reach: [Foundation]`, which rejects an observed indirect dependency path. An equivalent built-in forbidden-reach declaration was not verified in the reviewed DSL material. [Vendor explanation](https://blog.hello2morrow.com/category/software-architecture/page/2/), [connection grammar](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_grammar.html).

Sonargraph also has dependency-type restrictions and reusable aspects/templates. Its main DSL is broader than the subset supported by Zügel. Easement's reviewed configuration does not offer equivalent named connectors or rules differentiated by inheritance versus other dependency kinds. [DSL specification](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_grammar.html), [architecture requirements](https://eclipse.hello2morrow.com/doc/standalone/content/architecture_definition.html).

## Adoption, CI and trust are separate comparisons

Sonargraph-Build can fail CI on issues, including only new or worsened issues. Its machine report is documented as XML, with HTML for readers and a Java access library. That overlaps debt adoption and automated enforcement; it is not proof of an easement-shaped JSON CLI. [Build introduction](https://eclipse.hello2morrow.com/doc/build/content/introduction.html). `baselineReportPath` compares the current report to a baseline XML report and produces a changes-only HTML report. This is report-state comparison, whereas easement's `--diff` uses changed source lines. [Reporting Changes](https://eclipse.hello2morrow.com/doc/build/content/reporting_changes.html).

Zügel 26.6.1 documents Java, Python and C#, plus a subset of the Sonargraph DSL. MCP tools include `check_proposed_dependency`, `list_violations`, `query_dependencies`, `trace_dependency`, rescanning and baseline operations. It records both edit-to-edit and session-baseline changes. Model-dependent answers carry `sourcesStale`, `arcRulesStale` and `configStale`, with rescan/reload instructions. It explicitly leaves authoritative CI gating to Sonargraph-Build. Templates and dependency-type restrictions are not supported in its DSL subset. These are direct counterexamples to agent integration, baselines or trust signaling being individually unique. They do not establish an equivalent of easement's uncovered-file confidence fields: freshness and analysis coverage answer different questions. [Vendor's current Zügel reference article](https://blog.hello2morrow.com/2026/07/sonargraph-mcp-2/).

Evidence locator: the same article's section “Every answer says how fresh it is” names those three flags and states: “The remedy is always one call”. The article identifies its covered version as 26.6.1 and its release as September 30, 2026. [Exact primary page](https://blog.hello2morrow.com/2026/07/sonargraph-mcp-2/).

Lattix supplies another enterprise precedent: inherited `Can Use`, `Cannot Use` and `Must Use` rules, descriptions, external-system constraints and dependency-type filters. Rule ordering matters: lower-level rules can override inherited prohibitions, unlike easement's unconditional direct deny precedence. Its LDC CLI update report distinguishes all, new and resolved violations for build/CI integration. An equivalent agent JSON contract or uncovered-source confidence schema was not verified. [Lattix enforcement documentation](https://docs.lattix.com/lattix/userGuide/Monitoring_and_Enforcing_Architecture.html).

## Emerging open source: enforcement versus scores

| Tool | Verified exact enforcement and agent interface | Difference or evidence gap |
| --- | --- | --- |
| [MKanhan/archlint](https://github.com/MKanhan/archlint/blob/master/README.md) | Public MIT lite implementation documents Python, TS/JS, Go and Rust imports/globs. Its Markdown blueprint declares `layer ui = src/ui/**`, `ui -> services`, and `forbid ui -> repos`; deny overrides allow. Claude Code post-edit/stop hooks report drift; strict mode blocks. CLI `check` exits 1 on drift. | A concrete policy gate, not just scoring. External imports are ignored and analysis is explicitly nonsemantic. Baselines, cycles, public-API leakage, SARIF and Java/C# are advertised for separately licensed Pro, not established as public lite features. Named interfaces, slice identity, forbidden reachability and easement-style confidence reporting were not verified. |
| [Architect Genesis](https://github.com/camilooscargbaptista/architect#architecture-rules-architectrulesyml) | Documents Tree-sitter parsing for TS, Python, Go, Java, Rust, Ruby and PHP. `.architect.rules.yml` has `boundaries.banned_imports` entries with `from`/`to` globs and `allow_circular_dependencies: false`; `architect check` exits 0/1. It also has score and anti-pattern thresholds. MCP exposes `check_rules` alongside analysis, KB and refactoring tools; the CLI produces JSON reports. | Calling it only a scoring tool understates its documented overlap. Score history/regression tracking is not evidence of a violation baseline or Git changed-line gate. Compiler-derived resolution, named API interfaces, slice identity, forbidden transitive reach and incomplete-analysis trust fields were not verified. |

Neither README establishes an equivalent of easement's ownership and policy over source edges, manifest dependencies and Cargo feature parts. That is a bounded documentation finding; it does not establish a market-wide unique capability.

## A polyglot graph is not a service-call graph

Applying one policy to a Go backend and a TypeScript frontend does not establish an edge for `fetch("/orders")` into a Go HTTP handler. An indexer must actually resolve a relationship; sharing a report does not manufacture cross-language or network-call edges. Easement documents static references/imports and manifest dependencies, not HTTP endpoint/client matching. [Easement mechanism](../languages.md#how-it-works).

Sonargraph has a separate, explicit mechanism: its Java Spring Microservices plugin discovers annotated server endpoints and Feign clients, matches web calls to resources, and treats those edges as architecture-checkable dependencies. This framework-specific static matching does not imply universal runtime HTTP discovery for every supported language. [Plugin documentation](https://eclipse.hello2morrow.com/doc/standalone/content/spring_microservices_plugin.html).

Finally, SCIP itself is not a unique differentiator: ArchGraph documents SCIP-backed resolution, heuristic fallback and per-language reporting of the method used. It also distinguishes indexer availability from the capabilities of the deployed image. This is a counterexample for compiler-backed polyglot code intelligence, not verified equivalence to a declarative architecture gate or debt baseline. [ArchGraph language/capability documentation](https://docs.archgraph.dev/supported-languages).
